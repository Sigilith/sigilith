## Start with the research

**Sigilith** studies structural properties of symbolic systems through canonical segmentation, behaviour-preserving transformations, metric extraction, structural signature constraints, and classification.

The research concerns structure. Structural similarity alone does not establish a text's meaning, language, or decipherment.

**Primary paper**  
Nash, K. (2026). *A reproducible structural analysis of the Voynich manuscript via Sigilith v1.0.*  
[DOI and publication record](https://doi.org/10.17613/b5s4r-5t265) · [PDF in this repository](<Structural Analysis of the Voynich Manuscript Using Sigilith v1.PDF>) · [Citation metadata](CITATION.cff)

This repository is a research entry point containing the paper and citation metadata. It does not currently include an executable reproduction package.

## Runtime governance work

**ThreeLineage / TraceGuard** is my development work on execution boundaries, authenticated requests, audit records, and recovery behaviour.

The questions guiding that work are concrete:

- What is authorised to execute, and what happens when authorisation fails?
- Can an audit record be checked for alteration or missing links?
- What happens when a key is revoked, a request is replayed, or a process restarts?
- Which guarantees depend on the operating environment?

Runtime results need their own source, test commands, commit identifiers, and stated limitations. The research paper above is not a security certification of the runtime.

## How I approach contributions

1. Agree the problem and acceptance criteria.
2. Reproduce the failure or establish the baseline.
3. Make a focused change with a regression test.
4. Record the exact commit, commands, results, and remaining limitations.

Verification should be repeatable by a reviewer. A project name or generated comment is not test evidence.
